# 人工标注操作方案

> 后续修正：导航的主要审核单位现改为完整连续任务，实际可填写入口见`10_连续场景任务审核入口.md`。本页的单帧采集仅作属性/局部语义补充，不能替代连续目标搜索评价。

日期：2026-11-20。当前是操作设计，新页面尚未生成或启动。已有人工提交先检查复用，原文件不覆盖。本页不要求用户现在寻找旧localhost地址。

## 你要做什么

第一批20个不同画面，每图写两句自己会说的指令，共40条，用于检查填写流程。通过后分批扩展到约200画面、600条人工表达；如在同一张图上写三条，尽量指向不同对象或表达不同关系，不只换几个同义词。

主要工作是看图写话、点击目标、核对可见颜色与参照关系。无需画三维框、计算距离或判断车辆能否安全停车。

## 页面的顺序

1. 看原始画面，先不展示模型答案、预测框或自动指令。必要时播放截至当前帧的短片段；提交明确绑定当前帧。
2. 写一句你希望车辆完成的事。按日常表达，不必使用固定句式或系统内部术语。
3. 选择“明确目标 / 当前确无匹配 / 有歧义 / 看不清”。明确目标时点击它；歧义时可点多个候选，或注明需要进一步问清。
4. 如果用了公交车、卡车等参照物，另点一下参照物。所有左右/前后需要明确参照方向；说不清可以标注歧义，程序不能私自替你决定。
5. 对目标核对类别和可见颜色。清楚才填，看不清填未知；不强迫从一张图猜是否静止或是否可达。
6. 用一句话说明依据，例如目标在画面哪个位置、旁边是什么。不清楚的地方直接写出来。
7. 展开核对页检查目标绑定：程序提出的对象是否就是你点击的对象。绑定不准时修正或标待核验。
8. 提交后显示保存成功的记录编号，可刷新确认。页面应支持导出JSON备份，网络保存失败时能下载本地记录，避免重新填写。

示意：“靠近公交车右边的白色小汽车”；依据：“目标在公交车右侧，是白色轿车。”这只说明怎样填写，不应批量照抄作真实自然语言样本。关系可能依赖视角，需按画面和参照方向核对。

## 类别与困难情况

- 主任务六类：小汽车、卡车、公交车、摩托车、自行车、行人。
- 面包车可以选择界面里的“面包车”外观子类；在nuScenes六类主评价中按官方规则归到car/小汽车。保留原始子类记录，不强迫用户认为面包车就是轿车。KITTI按自己的官方标签规则映射，不跨数据集硬套。
- 道路、路边或车道可作为位置描述/背景参照，单独提供相应选项；不强迫把道路填成车辆。缺乏可靠标准的背景标注不计入六类对象识别主成绩。
- 看得到目标但模型没有框：仍标真实目标，不选“画面没有目标”。模型漏检由程序另外记录。
- 两辆目标都符合：标有歧义或可接受多个目标，不随便指定唯一答案。
- 太远看不清颜色：未知，不猜；清晰度差的样本也保留，不按模型是否会做筛掉。
- “不能接近”需道路或执行证据，单帧不确定时保持未知；人有疑问可以备注。

## 时间与批次

第一批20图用于实测每条耗时和常见错误，之后按每批20—30图安排。约600条指令和属性复核需要数小时累计人工投入，具体以首批实际时间估算；不将其描述为几分钟能完成。可分多次提交，记录批次与作者，不强制一次做完。

验证/评价中的属性和歧义记录全部核验；训练样本按错误类型抽样复核。若有第二人愿意审核，可安排部分独立复核；只有一位作者时如实记录，不能自动称双人一致。

## 我负责什么

我负责固定采样和数据划分、页面和图片、目标绑定提议、表单保存/导出、输入校验、已有记录导入、重复检查和训练数据转换。颜色、指令含义和歧义不能只凭自动生成冒充人工审核。

上线前必须实测图片能打开、提交成功、刷新后记录还在、JSON导出可重读。新的页面和接口使用新输入目录，不能直接照搬写到历史outputs的旧服务。给用户同时提供可验证的访问方式和离线包，确保SSH转发失败时仍能填写。当前未启动新服务，也没有可用的新地址。
