# 三维召回进一步优化方案

日期：2026-11-20。本文是基于现有代码和完整验证结果的方案，不代表新算法已经取得收益。本轮只分析和更新文档，不启动训练或大规模实验。

最新执行约定：用户已取消80%目标。以[配置对照Goal](12_召回优化下一阶段Goal.md)的显著净收益与提前停止规则为准；下文涉及80%的数字仅保留为历史计数推演，不作为本轮验收或继续运行的条件。达到显著改善并完成必要验证后，可以不再运行后续配置。

汽车与行人占全部漏失的81.55%。优先研究这两类有明确的分母依据，但最终评价仍保留所有六类。即使两类都达到至少80%、其余不变，整体也只有4157/5723=72.64%；达到全范围80%仍需其他类别一起改善。这是计数推演，不是效果预测。

完整类别证据：`outputs/results/nuscenes/validation/iterations/observation_tracking_comparison_20261120_v1/category_recall.csv`。

## 先修正诊断，再决定改动

当前代码有两个明确的过滤条件，但它们导致多少真实漏失尚未统计完整：

- `conceptgraph/slam/utils.py:gobs_to_detection_list` 使用 `max(cfg.min_points_threshold, 5)`，因此配置写4仍要求至少5个点；随后包围盒体积小于1e-6的观测也被丢弃。
- `conceptgraph/completion/depth.py:depth_support` 按深度分簇后选支持点最多的一簇。该规则在背景点更多时可能选择背景，须结合实际样本验证。

已有审计脚本的“足够深度”诊断采用至少4点，且没有完整重放实际入口的全部过滤与掩膜处理。它只能用于初步归因，不等价于实际三维观测可用性。上一轮审计还在预算内中断，不能从前缀外推全范围占比。

下一步应在真实入口记录每个检测依次经过：类别/置信度过滤、掩膜处理、深度筛选、点数门槛、退化包围盒、确认、关联与输出。先记录不改变算法，并核验基线逐帧计数一致。官方真值仅用于事后诊断；当前帧无证据和整个过去窗口无证据分别统计。

## 方案一：允许稀疏观测进入跟踪，独立判断形状能否建图

将“存在观测”“可以估计位置”“足够重建三维形状”分开：

- 无深度：保留二维轨迹和语义；没有可靠几何估计时不输出三维位置，不计三维命中。
- 1—4个真实深度点：保留位置假设、类别、时间、支持量与不确定性；同类多帧一致后可形成位置轨迹。点数不足不再意味着整条观测被入口删除。
- 点云充分：使用原点云与形状融合，供三维图和几何查询使用。

位置状态可以由稀疏证据维持，形状成熟后再接入点云对象；不要复制点、制造微小包围盒来绕过原门槛。远距离测量的协方差应更大；导航锁定需要独立的可信度判断，不能直接使用任意弱位置假设。

这是最优先的小试：固定原检测和深度输入，单独验证入口保留稀疏证据是否救回行人/小目标，同时报告误输出与身份变化。

## 方案二：保留多个深度解释，按质量融合

不要只因某簇点多就认定其为目标。对候选深度簇综合使用掩膜内部位置、深度离散度、与历史预测的一致性及遮挡关系；不简单选择最近簇，防止选中前景遮挡物。

融合权重来自检测置信度、有效实测点支持、深度分散程度、观测年龄和运动残差。位置状态与点云形状分别更新，避免一次背景污染把整条轨迹拖走。

使用过去多帧时，静态对象经自车位姿补偿后积累；动态对象必须先由过去观测估计运动并可靠对齐，不确定时保留独立假设。不得把移动对象的历史点云直接堆叠。原有传感器转换已经做了时刻/位姿处理，不把“重新补偿位姿”当作尚未实现的新算法。

还应单列“可见表面点云中心”和“物体几何中心”的差异，尤其是长车与局部可见目标。尺寸/朝向先验须来自合法训练资料，不能读取当前评价对象的真值尺寸来校正中心。

## 方案三：在真实观测上做两轮关联和不确定性更新

现有EvidenceAwareMapper已经有强/弱置信度确认，不能把重复增加门槛当成新算法。需要验证的是关联顺序和状态更新：

1. 高质量三维观测先与轨迹进行一对一匹配。
2. 剩余轨迹再用较弱观测续接；弱观测不能立即创建可信地图节点，弱新目标须经过跨帧独立证据确认。
3. 使用位置预测协方差构造匹配门控，联合已有外观特征和类别约束；固定的2.5/4米半径不应承担所有距离和遮挡情况。
4. 遮挡期间随时间增大不确定性并限制输出寿命；重新出现时核验身份，避免持续预测造成重复节点。

弱检测用于恢复轨迹有ByteTrack的一手方法依据；如何移植到本项目三维稀疏观测需要独立验证，论文结果不能直接当成本项目收益。[ByteTrack论文](https://arxiv.org/abs/2110.06864)

本轮因果跟踪原型的完整结果表明，单纯运动续接仅增加44次匹配，却降低IDF1。因此下一轮必须保留深度质量和现有外观证据，并共同评价身份，而不能只增加预测寿命。

## 方案四：证据不足时，再考虑三维检测分支

若完整审计显示大量目标持续没有二维框，或图像掩膜内始终没有可用三维证据，前述关联方案不能凭空恢复测量。此时应评估直接从原始LiDAR产生三维候选，再用图像/CLIP赋语义，与现有图像驱动候选去重融合。这样可以减少“二维框和掩膜必须先成功”的串行依赖。

CenterPoint直接估计三维中心、尺寸、朝向和速度，可作为这一分支的方法参考；其公开基准指标不等同于本项目3米逐帧地图召回。[CenterPoint论文](https://arxiv.org/abs/2006.11275)

这一分支涉及新模型、算力和输入使用方式，超出目前下一阶段Goal“不下载模型、不训练”的预算。先完成前三项证据审计与小试，再单独安排。引入nuScenes预训练权重前须核查训练场景重合，重合场景只能作为工程回归证据。

## 建议的实验顺序

1. 用现有缓存补齐全部38场景的准确过滤日志，确定两项主要损失机制。
2. 冻结四个条件：现有基线；稀疏观测与质量估计；两轮关联；二者组合。最多三个新配置，避免大量试参。
3. 先用预先固定的两个验证场景测运行时间、峰值内存和机制正确性，再串行完成全范围评价；不得按小试成功与否筛掉最终评价场景。
4. 评价固定1508帧、5723次对象出现和3米门限，同时报告精度、F1、IDF1、重复节点、中心误差与日志级配对区间。只在验证/调试集选方法，不拿已使用测试继续调参。
5. 预算仍按下一阶段Goal：总运行最多2小时、新增最多2GiB、空闲低于20GiB停止。先解决0.5核CPU/2GiB内存下的串行和流式执行，不并行加载多个完整点云地图。

以上均为待验证假设。当前任务不设置绝对召回目标；任一候选在完整验证范围内达到经过多重比较校正的显著召回增益，且F1与IDF1点估计不下降、必要验证完成，即停止新增实验并交付。具体标准以配置对照Goal为准，默认配置不自动切换。

Qwen另需先报告候选包含目标的比例，以及目标在候选内时的选择能力；对候选缺失和模型选错分别处理。后续训练应以真实目标、歧义关系与困难负例为基础。本轮优化优先集中在上游三维观测，不启动新一轮LoRA。
