# Qwen作用与指令设计

## Qwen是“听指令、看候选”的助手

可以把系统分成三个人：建图模块负责记下周围有什么、在哪里；Qwen尝试理解人想找哪个对象；规划控制模块检查车辆能怎么走、再执行。Qwen不是整个系统的大脑，也不是建图必需部件。

比如“开到前面那辆白车附近，找个能安全停下的位置”是一条示意指令，不表示现有训练集已有这条带可靠标注的样本。系统需要拆出小汽车、白色、前方等条件；从地图里找对象；最后由道路、车身和控制检查决定是否能接近。Qwen不能自己把“不安全”改成“安全”。

## 代码支持的三个任务

| 任务 | 用人话解释 | 没有Qwen怎么办 |
|---|---|---|
| 指令解析 | 从一句话里提取类别、属性、参照物和关系 | 规则解析能处理支持范围内的常见表达，复杂表达可能失败 |
| 对象属性 | 看被裁出的目标小图，尝试判断颜色等 | 使用已有可靠属性；没有证据的属性不能凭空补上 |
| 候选重排 | 地图给出若干对象，让模型判断哪个更符合指令 | 默认导航使用类别、文字匹配、距离与几何关系评分；CLIP检索另有独立对照 |

接口在 `conceptgraph/vlm/qwen_semantic_delegate.py`；规则在 `conceptgraph/navigation/semantic.py`；合作和回退在 `conceptgraph/navigation/pipeline.py`。三个接口存在，不等于每次实验都调用了三个任务。30场景测试中的新图数据Adapter重点评价的是候选重排，不能把成绩解释为完整图像理解和导航能力。

## 去掉Qwen还能建图和导航吗

能继续检测、分割、恢复距离、融合对象、维护关系图；能对规则支持的指令或给定目标进行目标选择和路线规划；在其余输入、控制器和安全条件满足时可继续执行导航。是否选对和实际到达仍需评价，不能因为程序可运行就默认成功。

可能受影响的是超出规则覆盖范围的表达理解与某些属性、歧义对象的判断。当前实验并没有证明新Adapter普遍提升目标选择，所以不能写成“没有Qwen就无法建图导航”。Qwen也找不回前端根本没有提供的对象。

关闭Qwen时，`parse_navigation_query`按类别别名、颜色词、关系词、否定词和固定句式解析；`score_text_similarity`比较指令词和对象文字标签；`rank_candidate_targets`再结合对象距离与真实几何关系排序。随后目标选择器检查道路可达性、接近位置和车身约束。这是人工编写的规则流程，不能保证理解任意自然语言。前端使用CLIP特征、另外设置CLIP检索基线，都不代表默认规则解析器本身在调用CLIP或大语言模型。

## 为什么当前query看起来不像导航

这批是程序按模板生成的受控任务。例如“选择最近的小汽车”“以公交车为参照，选择其左侧最近的小汽车”，以及要求可靠证据才授权的故障指令。

当时的设计目的是分开检查类别、关系、否定、多个候选、无匹配、证据不足、过期和冲突；这适合做功能诊断，方便确定标准答案。但它们不包含完整的真实用户语言，也没有充分描述停车位置、车道、可接近性、连续对话或执行要求。把它们称为已充分覆盖自然语言导航的数据集不合理。

特别是“只有当前证据可靠且目标静止时才授权”属于程序内部的安全条件，不该要求普通用户每次都这么说。它可以作为受控安全诊断的文本，但不应该成为自然导航指令的主要写法。真实指令表达人的目的，证据是否可靠则由系统内部独立检查。

数据还存在明确不足：训练只有51个不同画面；459条中348条标准回答不选择对象；人工逐条审核数为0。它可能把模型训练得过于保守。这里既有任务分布问题，又有感知候选缺失和自动配对不确定性，不能只归因于人工标错。

## 加入Qwen是否已经比不用好

现有30场景测试主组共600条受控模板指令；其中264条确有目标，另336条应当不选目标。这不是自然语言导航到达率。

| 方法 | 264条有目标指令选对 | 336条无目标指令却乱选（越低越好） |
|---|---:|---:|
| 不用Qwen：按类别找最近目标 | 82/264，31.06% | 55/336，16.37% |
| 不用Qwen：完整几何规则（更保守） | 31/264，11.74% | 4/336，1.19% |
| 原始Qwen | 39/264，14.77% | 185/336，55.06% |
| 旧微调Qwen | 55/264，20.83% | 247/336，73.51% |
| 新图数据微调，seed17 | 19/264，7.20% | 80/336，23.81% |
| 新图数据微调，seed29 | 1/264，0.38% | 7/336，2.08% |
| 新图数据微调，seed43 | 10/264，3.79% | 53/336，15.77% |

旧微调相对原始Qwen在“有目标选对”上有提升，但误选也增加；新微调减少乱选，却漏掉更多真目标。目前不能声称Qwen普遍超过不用Qwen的规则方案。不同规则的保守程度不同，也要同时看选对和误选。

证据：`outputs/results/nuscenes/test/evaluation/retrieval_summary.json`，筛选cohort=distribution_preserving。加入Qwen不改变地图中缺少目标这一事实，语义成绩也不能当作建图召回或实际到达率。2026-11-18本轮改进的是检测和对象建图，未新训练Qwen，不把本轮建图收益记在Qwen名下。

## 后续要补什么（本轮未开始生成或训练）

真实人看图说出的指令应与模板诊断分开。每条记录绑定当前画面、官方对象身份或明确无匹配、可接受的目标、参照关系和必要的人工审核；颜色不清楚就保留未知。正目标、无匹配和证据故障分别评价，避免“不选就高分”。同一场景的模板改写不能当作新的独立画面，训练和测试也不能只换一句说法。

导航还要额外标清安全接近区域与执行要求；“选中小汽车”只是其中一步。现有用户提交的人工指令保存在 `dataset/annotations/natural_navigation_submissions/`；不自动把这些已用于分析的记录变成新的未见测试。
