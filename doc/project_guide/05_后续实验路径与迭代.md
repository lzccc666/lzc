# 后续实验路径与迭代

用户要求：下次生成结果也实际写入整理后的目录，而不只是增加查看入口。该约定已写入项目根目录 `AGENTS.md`。

## 新的默认路径

```text
dataset/processed/…                         新生成的预处理输入
dataset/qwen/…                              新生成的Qwen监督数据
outputs/results/nuscenes/validation/iterations/<run_id>/
    release.json                            运行前冻结的配置、范围和预算
    source_snapshot/                        运行代码快照
    scene-xxxx/detections/                   如本次重跑前端，保存真实检测与掩膜
    scene-xxxx/frames.jsonl.gz               逐帧地图预测与隔离评价
    scene-xxxx/report.json                  逐场景统计
    report.json                             全量汇总，完整跑完才生成
outputs/reports/mapping_iteration_20261118/   本轮运行日志与跨实验说明
```

创建新run使用 `conceptgraph/project_paths.py`。它检查路径字段并拒绝覆盖已有run。历史脚本仍按旧协议保留，不在本轮批量改写其路径或哈希；新的实验入口不再使用旧输出根。

## 当前可用入口

```bash
# 只读诊断现有地图为什么漏目标，不重跑模型
python -m conceptgraph.completion.mapping_recall_diagnosis --run-id <新的诊断ID>

# 同一前端输入下，重建地图并比较弱检测证据确认
python scripts/run_mapping_iteration.py --run-id <新的建图ID>

# 真正调用GPU，比较类别提示词和分辨率；只有二维框诊断
python scripts/probe_vehicle_detection.py --run-id <新的检测诊断ID>

# 真正调用GPU完成检测、分割、特征提取和连续对象建图
python scripts/run_vehicle_frontend_iteration.py --run-id <新的完整建图ID>
```

这些命令默认只用验证／调试场景。输入是已有真实RGB、过去LiDAR距离图、内参和位姿；标准答案只进入评价段。命令不是建议反复重跑，查看本轮结果应直接读已有report。

## 本轮改进做什么

1. 漏失诊断分开统计没有同类检测框、建图前置信度过滤、距离点不足，以及有框有距离但三维位置或融合未匹配。投影框只作诊断，不称官方mAP。
2. 双置信度建图保留较弱检测，跨不同帧且有真实深度支持后再正式输出弱目标；同时保留仅调低门限的对照，不能把门限收益全归到新结构。
3. 新前端把行人检测提示改为person，并统一回写项目类别pedestrian；使用960输入分辨率。六类交通参与者的检测、MobileSAM分割和CLIP特征都重新真实运行。
4. 新前端实验评价六类交通参与者对象图，没有验证全部静态环境要素和车辆控制；未直接替换在车上运行的完整导航配置。道路、车道和其他静态要素的地图职责仍需单独保持。

最终主指标继续用原范围、原三米同类一对一匹配规则，并同时报告召回、输出匹配比例、F1、身份一致性和位置误差。近距离小汽车的高分作为附加诊断，不能覆盖全范围低分。
