# 目录整理说明

总入口：[项目导航](../../项目导航.md)。目录清单见同目录 `目录分类索引.csv`；源码文件清单见 `源码文件索引.csv`。

## 本次实际整理

1. 将阶段9之后 `outputs/project_v2/thesis_completion_v1/data_manifest/` 的预处理输入迁到 `dataset/processed/preparation_history/`。其中当前nuScenes输入进一步分出 `dataset/processed/nuscenes/validation/` 和 `test/`。
2. 将阶段9之后结构化训练数据迁到 `dataset/qwen/structured_supervision_history/`；五个图任务数据版本迁到 `dataset/qwen/official_graph_v001`、`official_graph_v002`、`real_graph_v001`、`real_graph_v002`、`real_graph_v003`。
3. 旧路径均保留软链接。历史JSON里保存的绝对路径、旧实验脚本以及哈希核验仍可读取原来的内容。
4. 在 `outputs/results/` 建立按nuScenes、KITTI、Qwen、CARLA分类的结果入口，表格、图片和复现记录另列。文件不复制，不丢弃失败记录。
5. 人工记录、共享卷KITTI输入、模型、原稿建立分类入口。共享卷文件不搬迁。阶段1—8原始输入和模型不搬迁。
6. 另外将输入树中39个旧 `exp_*` 预测结果目录入口分离到 `outputs/project_v2/thesis_completion_v1/reorganized_results_20261118/`，原处保留兼容链接。它们原本就是指向已有前端输出的链接集合，没有生成新的预测文件。当前验证组检测文件直接从 `outputs/results/nuscenes/validation/detections/` 查看。

预处理清单里也有转换日志、传感器对齐报告，跟着对应输入版本保存；它们用于解释输入如何生成。输出目录中原来的 `inputs` 有些只是链接，有些是为复现固定下来的逐回合传感器证据，不能一概删除。

## 为什么没有强行移动所有旧实验源码

`conceptgraph/` 是业务代码，`scripts/` 是命令入口。较晚实验还把361项脚本和缓存条目混在结果目录的 `source/` 中。许多脚本用自身位置推算结果路径，直接搬走会把路径改错；有些脚本的字节哈希也已写入冻结协议。

本次把其统一入口放在 `scripts/experiment_archive/public_20261115/`，并生成源码索引，保留其历史实体位置与字节。这个目录明确视为冻结实验驱动脚本，不再把它当今后新增业务代码的目录。`source_bundle/` 是当时执行代码的快照，作为结果溯源资料继续保存。后续新业务代码应进入 `conceptgraph/`，新命令进入 `scripts/`，新结果进入 `outputs/`。

## 为什么保留旧名字

历史实验包含“哪些数据被看过”的重要记录。将development直接改成train会误导为这些场景都用于训练；将已看过的测试重新称为从未开启也不正确。因此只在新入口使用容易理解的名称：训练、验证／调试、测试；文件内部历史ID、split字段和报告不改。

## 可核验记录

`outputs/reports/organization/` 保存迁移计划、整理前Git状态和diff、原文件SHA-256、整理后核验报告。核验逐项检查旧路径仍可读取同样的文件、原软链接没有新增断链、新分类入口有效。原先已断开的链接另记，不冒充本次新增故障。

本轮没有删除文件，没有覆盖原稿，没有改标签、数字、业务代码或模型权重，也没有推送Git。
