## 3. A线：先查清基础链路损失

固定当前改进YOLO、MobileSAM、CLIP以及同一RGB/深度/位姿缓存；优先复用1508帧已有真实检测文件，不重复运行或复制大体积前端。先按固定清单抽取约80帧验证运行成本，之后用完整38场景检查结论。

采用以下分层输出，避免用二维召回与最终建图召回的差额冒充关联损失：

| 层次 | 保留什么 | 能判断什么 |
|---|---|---|
| A0 原始二维检测 | 框、类别、分数、掩膜 | 是否看见对象；二维诊断单列 |
| A1 当前帧三维观测 | 同一深度恢复与相同输出准入规则 | 单帧位置是否正确，距离支持是否足够 |
| A2 当前跨帧关联/融合 | 当前一对一关联与动态更新 | 融合带来的恢复和损伤 |
| A3 正式输出确认 | 强观测或弱观测多帧确认 | 等待确认额外减少了多少误输出和真目标 |

纯关联比较中A1与A2采用同一强度/深度准入，先独立隔离确认机制；弱观测确认再做单独消融。每帧按同一官方对象身份列出：融合前正确、融合后正确、被融合救回、被融合弄错，以及未确认/过期等状态。对相邻同类对象产生的配对歧义明确标记，必要时可视化复核，不能将自动中心配对宣称为人工真值。

同时检查：时间戳单位与位姿方向、深度是否来自允许的当前/过去传感器、尺寸/中心含义、评价范围、预测和GT是否一对一、分子分母是否对称。发现评价错误必须对所有方法统一纠正。

## 4. A线：按诊断选择真实改进

### 4.1 深度和几何

保留原始深度质量处理作为对照，候选改进限于：掩膜内空间连通与距离一致性、排除明显地面/背景混入、按深度支持质量对多帧位置加权、对长车与稀疏观测记录位置不确定度。

从可见表面恢复的中心与官方三维框中心并不总是同一点。不能按官方答案或类别手工平移当前预测去凑评分；若学习尺寸/中心估计，只允许在训练数据拟合、验证集选定后冻结，并保存附加数据与训练成本。

### 4.2 跨帧关联

候选方案：用最近历史位置和真实时间差预测下一位置，按位置不确定度限制配对，再结合类别、外观和框重合做一对一匹配。先高置信观测关联，再让低置信观测续接已有轨迹；低置信新对象通过独立多帧证据确认。

运动目标更新当前几何，避免累加出拖影；静态对象按观测质量融合。保留短时失踪状态与明确期限，避免很短遮挡就换身份，也避免旧对象永久残留。位置预测不能访问未来帧或官方轨迹。最多比较3组事前冻结的参数组合，不做无界阈值搜索。

这部分借鉴公开跟踪思路，不冒称全新算法。ByteTrack的高低分关联与AB3DMOT的运动跟踪作为参考；若只接入某一组件，命名为“参考某方法的模块”，不声称完整复现。

### 4.3 感知补充的触发条件

只有诊断表明“当前帧根本没检测到”仍是主要瓶颈，才试一次前端补充：固定分辨率提升或仅对小目标区域二次检测。所有方法披露输入分辨率、重复框处理与耗时。先做固定小样本质量/成本试验，不立即重做1508帧，不重复下载RAM。

YOLO/SAM微调暂不设为必做项；只有看到足量可靠训练标注和明确失败模式，才决定是否值得训练。

展示顺序：全范围主表→距离分组→去重覆盖与连续稳定性→相同场景的逐帧可视化→失败类型和成本。成功案例按预定条件选，另列典型失败，不用成功案例替代统计。nuScenes和KITTI分表。

工程期望是全范围F1与IDF1各增加约3个百分点以上；这是优化目标，不是承诺。任何提升都要报告按采集日志配对重采样的区间；区间不足以支持可靠优势时如实说明。输出匹配比例大幅下降而仅召回增加，不直接认定为整体改进。

## 7. B线：Qwen的创新点应具体是什么

候选贡献：把自然指令、目标局部图像、对象关系和多帧证据结合起来，完成“可解释的场景图目标定位”，对看不清、候选缺失和歧义明确输出不同状态，再由规划控制模块检查接近条件。

三项能力：①提取人说的对象条件；②从目标裁剪判断有证据的属性；③结合关系与属性从候选中选目标。距离计算、坐标变换、车道可达性等确定性工作由程序完成。输出建议包含指令解析、目标编号或可接受集合、证据对应编号，以及selected/no_match/ambiguous/unknown状态；解释正确性抽样审核，不凭一段好听文字认定正确。

基座继续采用本地Qwen2-VL-2B-Instruct，先不新增大模型。LoRA只是训练手段，不能仅凭“用了Qwen并微调”就认定创新有效；有效性要由相同输入下的微调收益、去掉图像/关系后的消融和整体目标选择结果支持。

## 8. B线数据构建

旧数据保留作为历史受控诊断：459条、51画面、348条空选择；不能简单增加改写数量冒充新增场景。新建`dataset/qwen/natural_graph_v004/`，并使用独立标注批次目录`dataset/annotations/natural_graph_v004/`；本方案阶段尚不创建这些数据目录。

### 8.1 数量与划分

先20个画面、每图2条指令，共40条，检查流程和标签一致性。后续建议扩展到约200个不同画面、600条人工自然指令，并核验所指对象的约200—400份去重属性记录；旧记录先检查是否可复用，不重复要求用户填写。

600条是首轮训练/验证用的数据规模建议，不保证能支撑细小优势的统计结论。优先选择不同日志、距离、类别和语言关系，保留远处/遮挡/无匹配情况；不要按任何方法是否做对选图。较难情形可定额采集，但需要标明这是任务定额分布。

划分先于采集和训练：按采集日志与对象轨迹隔离，训练/验证/留出评价约60%/20%/20%，随日志实际规模调整；训练至少覆盖多个日志，验证至少2个日志，留出尽量至少3个日志。一个画面的所有指令、裁剪、任务和改写只能进一个集合。数据不足则缩小结论，不把同帧改写拆去测试。

现有38场景已反复用于建图调试；在其中采集的新语言可以作为Qwen未参与训练的指令留出，但必须说明视觉场景已有开发历史，不能声称整个系统从未见过。新的全链路未见测试需要另行取得且事先锁定的数据。已有测试成绩和人工提交只按原角色复用，不重新包装成未开启测试。

### 8.2 样本与答案

先让人看原图自由写话，提交后再展开对象/属性复核，避免模型预测或答案模板影响表达。人点击的目标先绑定官方实例或可接受集合；相邻框重叠、目标中心投影不准时必须复核，无法可靠绑定就标待核验，不强行分配身份。

每条记录保存：数据集、日志/场景/帧、原图哈希、作者、原始指令、目标点击位置、可接受目标身份、类别、可见属性、参照物与关系、歧义/未知、审核状态与修改历史。模型输入不含官方实例、答案或人工解释性标准答案；官方身份和目标集合只用于生成监督与独立评价。

每帧的真实候选来自冻结的新建图版本，包括漏目标、零候选和重复候选。先标清人的真实目标，再独立判断地图是否包含该目标；不能把候选漏检改写为“人想找的对象不存在”。相机画面没有可靠证据时，运动状态、停车位置与安全性保持未知。

训练采样初始建议为有明确目标约60%、真实无匹配约20%、歧义/未知约20%；候选漏目标独立记录，并合理采样。它只是待验证的训练采样起点，不修改原始数据、不对测试重采样。目标存在且已进入候选的样本应足够多，避免重演75.82%空选择。

用人工指令产生三类监督：解析标签、对象属性标签、候选选择标签。同一条指令可支持多个任务，但只算一条原始人工表达。程序生成的变体标注自动来源，人工确认也不改称人原创；生成器只看训练数据，不读留出指令。同义改写、编号排列、同类干扰对象帮助训练，不能增加独立场景计数。

### 8.3 人工工作

用户只需看图写话、点目标、核对颜色/参照关系；无需重画三维框、计算距离、猜测运动状态或安全停车条件。详细流程见`09_人工标注操作方案.md`。首轮20图用于检验表单，暂只进入训练/验证准备；正式留出批次单独保管，作者可以提交自己的标签，执行代理在模型冻结前不分析其测试内容。

单人标注如无法安排第二人复核，则如实记录单人来源；争议样本二次核验，不能声称独立双人审核。验证和留出中的人工属性/歧义标签全部核验，训练数据可按错误类型抽样复核。

## 9. B线输入和训练方案

候选输入统一采用指令、最多8个固定候选、各自位置/关系/观测质量及可选裁剪。保留“真目标被候选上限挤掉”的记录；用同一与答案无关的候选生成器。所有对比共享同一次候选顺序和编号，训练可随机排列，不能让模型记住编号。

同一基座分别训练三个单任务LoRA小试：解析、属性、候选选择，再训练任务均衡混合版本。单任务分别从基座开始，避免在同一Adapter上顺序覆盖。混合时加任务标识和统一结构输出，按任务而非原始行数采样，监督只作用于答案部分；验证结构正确、图像是否真正进入训练、答案是否泄漏到输入。

先固定小规模超参数（建议LoRA r=8/16二选一，首次固定一项；仅验证损失异常时调整），学习率与步数由验证集选定。属性任务必须实际读取图片，不能把图片文件名当作图像输入。训练记录包含图像张量和对应样本审计，不仅看损失下降。

候选选择为主任务；若解析基座已足够好，或混合训练拖累它，则保留基座解析或独立Adapter。只有小试支持时才增加“主任务预热后混合训练”的版本，不能将LoRA直接相加当作联合训练。

最终候选方案验证后固定，使用17/29/43三个种子训练，报告均值和波动。核心模块消融先用固定种子；如果结论依赖种子，增加复核而非只报最高种子。时间预算到达时标记未完成项，不擅自无限延长。

| 多任务版去关系信息，重新匹配训练/验证 | 场景图关系是否有用 |
| 多任务版去观测质量/时间信息，重新匹配训练/验证 | 多帧证据是否有用 |

去掉模块后，保留模型、样本、更新步数和候选清单，明确是重新训练的模块消融。单独推理时临时遮掉信息只能称输入扰动诊断，不与重新训练消融混称。若资源预算不足，先完成图像和关系两项核心消融，时间证据列为待做，不假装整套已完成。

比较范围分为图文字输入和图像＋图输入，表中披露各方法能读什么。证明微调有效时，原始Qwen与LoRA必须使用同样图片、候选、上下文、提示、输出校验、超时及回退条件。规则和CLIP对照尽量使用相同可得证据；它们不支持某输入时明示，不能把不平等输入收益全部归于微调。

不用人为把基线提示写坏，不降低其候选上限、不减少图片、不额外收紧其超时。人工颜色标签不作为推理时可免费读取的属性；任何属性预测器的调用和延迟都算进成本。

## 11. Qwen评价与“有效”的判断

解析：关键字段正确率、整条解析正确率；属性：清晰可见样本正确率、未知判断与乱猜率；目标选择：目标在候选时选对率、包含感知漏失的全链路选对率、无匹配误选率、歧义处理。每项列分子/分母，并列耗时、超时/格式错误、原始模型输出与回退后的系统输出。

全链路选对率受候选覆盖限制。语义模型不能找回候选根本没有的对象，因此同时报条件成绩与全链路成绩；不能只给条件成绩贴“系统准确率”标签。错误目标拒答、正确目标拒答分别计数，保证高拒答率不能换来虚假的高准确率。

工程期望：目标已在候选时，比同输入原始Qwen及最强非Qwen对照提高约10个百分点；全链路目标选择相对当前最好方法提高约5个百分点，同时检查无匹配误选代价。这是期望，不作为数据筛选标准，也不保证实现。

声明“创新有效”需要：同输入微调比较支持收益；与强规则/CLIP至少在预先定义的关键复杂任务上有收益，且完整混合任务成绩也公布；核心图像/关系消融支持相应模块作用；三个种子与场景/日志配对区间支持结论；不能只有某个成功案例。若仅在特定任务有效，就限定贡献范围，不宣称普遍提升。样本量不足时报告区间和限制，不能保证正结果。

## 12. 顺序、预算和停止条件

| 阶段 | 产物 | 通过后做什么 |
|---|---|---|
| P0 协议和数据核查 | 冻结范围、基线、输入与预算；20图采集流程 | 基础链路诊断与用户标注可并行推进 |
| P1 基础链路归因 | 关联前后正确/错误明细、深度问题表 | 只针对主要损失实现候选改进 |
| P2 基础改进与消融 | 完整38场景比较、KITTI 1000帧回归、模块消融 | 固定用于Qwen的对象地图 |
| P3 人工数据小试与扩充 | 40条试填审核，再扩到建议600条 | 只有标签、划分和图像输入核验通过才训练 |
| P4 Qwen小试与消融 | 原模型、规则、CLIP、单任务/混合及核心消融 | 选定方案后做3种子和冻结评价 |
| P5 接入与交付 | 全链路目标选择/锁定/路线、表格、案例与复现 | 汇报完成项、失败项与证据限制后结束本轮 |

现磁盘约30GiB空闲，20GiB为停止新增大文件底线。首轮新增总预算8GiB：建图中间与结果2GiB；标注缩略图/裁剪及数据0.5GiB；Qwen检查点/必要优化器状态3GiB；评价、可视化与日志0.5GiB；余量2GiB。原RGB和前端缓存引用复用，避免复制。估算超过某项配额时先缩小新产物，不删除历史来硬挤。

准备/诊断/基础改进首轮计算上限4小时；Qwen首轮训练与评价预算8 GPU小时。先用80帧和40条记录测实际速度再更新估算；人工采集时间单独计算，不能把它隐藏进GPU耗时。达预算或20GiB空闲边界时保存现状、报告已完成项和剩余工作；不无限扩模型、种子或场景。上述是运行预算，不是完成时间保证。

新数据输入真实写到dataset，新源码写到conceptgraph或scripts；结果用`conceptgraph.project_paths.experiment_directory`创建新run：

```text
dataset/annotations/natural_graph_v004/<batch_id>/
dataset/qwen/natural_graph_v004/{train,validation,holdout}.jsonl
dataset/qwen/natural_graph_v004/{manifest,audit}.json
outputs/results/nuscenes/validation/iterations/<run_id>/
outputs/results/kitti/validation/iterations/<run_id>/
outputs/results/qwen/train/iterations/<run_id>/
outputs/results/qwen/validation/iterations/<run_id>/
outputs/results/qwen/test/iterations/<run_id>/    仅在该批明确具有相应评价角色时使用
outputs/reports/<campaign_id>/
```

每次执行先保存release.json、源码快照、权重/数据哈希、随机种子、传感器范围、方法输入与资源限制。代码中不读取评价标签决定关联、候选、门限或路线。

本轮完成的定义：约定范围跑完、完整表格与消融有证据、人工数据审核和模型输入审计完成、剩余失败如实列出、交付能复现。若Qwen未达预期，应交付原因和负结果，而不是继续无期限搜索直到碰到一个正分。
