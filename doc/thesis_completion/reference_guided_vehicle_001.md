# 中心线引导的运动约束搜索：后验开发协议

原真实HD地图诊断已经查看结果，故本版本仅为明确的后验开发改进，绝不进入30个新封存场景。保留原228条件、7源快照及全部失败。改进动机为原Hybrid在7个有效几何场景的21次条件中18次耗尽3秒预算、3次耗尽离散基元；不能由此推断正确路线不存在，或在未经对照前断言失败由转角离散造成。

新业务模块另存`conceptgraph/navigation/reference_guided_vehicle.py`，不修改七组活跃冻结业务源。中心线仅为同一已声明地图路线先验，不使用目标对象真值、未来传感器、原成功路径或点A*结果。车辆、路面与静态预测障碍、后轴初始扰动、出口位姿、终点评价和实际控制器与原协议相同。没有语言目标，所有参考位姿到达的语义到达信用为0。

算法在同一前向自行车模型与转角变化率限制下，先尝试沿地图参考线的连续纯跟踪引导，每0.1秒保留真实积分状态并检查整车扫掠、连续方向和固定有向车道身份。引导失败时从其已检查前缀继续有界状态搜索。搜索建议为当前2.5米前视引导转角、其±8度、零转角、原±16/±32度；每个建议积分10步；不反向、不卡位姿或沿折线直接移动。中心线引导是搜索建议，不授权绕过任何几何或拓扑条件。

保持地图原多边形与孔洞、2米连接端点界、0.05米规划车身余量和原执行守卫。规划返回需距目标≤0.65米、航向≤12度且完整车道见证可达到出口。无解/超时返回空路线，已搜索前缀另作诊断、不冒充完整路线。规划起点不能因车道重叠直接进入后续lane；连续车道阶段加入搜索状态，不能用末端可达集合替代全程见证。

全量仍取原38任务，固定种子17/29/43，共两规划器×38×3=228次。两规划器分别为原Hybrid和新引导搜索，均3秒/2000次状态扩展，所有前导工作计入预算；新引导每个实际扩展算一次。每种子/场景按预先固定序号奇偶交换两个方法顺序，不按结果排序。实际耗时可因单个不可中断几何操作略超截止，不据共享CPU做独占实时性能结论。点A*原异预算结果只作历史参考，不混入本次配对优势结论。

先运行有针对性的普通回归（曲线跟踪、车辆限幅、不可通行屏障、道路孔洞、非法连接与预算），再固定原首任务元数据失败和首个ready任务seed17的两方法试跑。试跑记录不得替换，失败照常保留。只要求普通功能回归与安全证据有效，不以首个真实场景规划/到达成功作为扩大门槛，避免按成功选场。全量实际执行使用现有`execute_corridor`，不执行规划器自产成功标志；另以保存实际控制、独立连续车身和原始地图/连续后轴/完整连接/终点保持审核。全部228条件必须保留；未知、无路线、停车、执行失败均有分母。

总墙钟3600秒、存储1GiB、最低剩余6GiB；隐藏CUDA，单共享CPU作业，记录与原GPU主矩阵重叠。新源及协议在运行前保存SHA并封存独立源码归档，不修改排队中的旧实验版本。正式结果按11log配对bootstrap4000次、种子5723，报告路线、实际运动和参考位姿到达、控制/规划耗时分开；三扰动不增加独立任务/场景数。新测试不解封，不撰写论文正文，不把开发提升称为封存泛化成绩。
