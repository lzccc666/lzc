# 真实时钟传感器故障协议 v1

本协议只新增独立故障入口，原450主矩阵、后续450语义缺一与其66个冻结依赖不改。开发仿真、控制功能实验和新封存测试分别报告，所有阶段与Goal仍未完成。

## 正式GPU条件与预算

事前固定原50任务中每个配置的`positive0`，共10任务、10配置、3种道路家族，使用17/29/43三种子。新Adapter完整三语义任务在六条件分别重新运行，共180次；先在config00-positive0/seed17实际执行六条件试跑，试跑不增加独立任务数，不复用主矩阵baseline。预备清单不计模型调用。

|条件|对推理观测的改动|
|---|---|
|baseline|经过同一包装入口，保留原观测，不注入故障|
|sensor_blackout_4s|首次满足运动触发时，感知线程真实阻塞4秒；控制心跳持续运行，传感器时间戳不刷新|
|lidar_dropout_80pct|有效稀疏深度以0.2概率保留；不产生原来没有的深度点|
|depth_noise_02m|只对有效深度加入标准差0.2m独立高斯噪声，再按实际PNG毫米量化；零深度保持零|
|pose_noise_025m_2deg|相机观测位姿XY加入0.25m标准差噪声，世界yaw加入2度标准差噪声；物理车态和评价器不改|
|detection_dropout_30pct|在真实YOLO/MobileSAM/CLIP输出后，以0.7概率保留整条对齐检测，不改类别词表与原图来源|

触发只访问当前实测车态：相对首帧欧氏位移至少0.5m、速度至少0.2m/s。除一次4秒阻塞外，扰动持续时间为6秒，是否施加按观测开始时的真实单调时钟确定。随机源固定为物理种子与帧序号。未运动、未触发、没有有效深度、随机未移除检测等情况分别保留，不计故障恢复成功，也不移出180分母。

正式条件保持原真实时钟协议：90秒控制预算、传感器TTL 1.5秒、语义TTL 30秒、候选规划预算10秒、Top-K=3、独立0.1秒控制心跳、同一车辆与到达评价器，单子进程240秒上限。六次GPU试跑预算2400秒/1GB，180次全量43200秒/8GB；始终保留至少6GB余量。前置完整结束、GPU无其他CUDA进程且至少16GB可用时才启动，不自动重试失败或中断任务。

所有条件使用同一新Adapter、真实前端与控制器。动作后的RGB/深度可能不同，配对的是任务/配置/种子，不能声称故障后闭环输入逐帧相同。统计使用全部冻结记录并按10配置聚类；生成路线、选对、正确锁定和实际到达分开。无结果保留unknown和失败信用，零暴露不获100%安全。没有独立有效参考时不报告SPL。

## 输入与控制证据

每帧保存未改动传感器、实际有效PNG/相机位姿、未改动真实检测与有效gobs、保留索引、原图/深度/检测SHA、故障开始/结束及控制时钟基准。故障元数据只写`fault_events.jsonl`和独立清单；旧建图器不能接受额外gobs字典字段。检测可视图表示未删减真实前端输出，有效输入以保存gobs和保留索引为准。

场景对象真值、可接受身份与安全终点仍仅进入原独立评价器。噪声是离线定义的合成误差，未按真实车载传感器标定；位姿扰动只影响相机观测，不代表完整里程计漂移。静态mesh、地图、车辆模型范围之外的动态交通安全未证明。后台迟到/异常/非法模型输出的完整故障验收另列，不能用这些传感器条件替代。

入口：`conceptgraph/completion/realtime_faults.py`。矩阵与排队器：`source_bundle/realtime_fault_matrix_001.py`、`realtime_fault_after_semantics_001.py`。后者先等待450主矩阵、450缺一/750合并统计和CPU试跑全部完整，再按冻结清单运行GPU六次试跑与180全量。完整结果存在前不计其完成。

## CPU真实前端试跑与控制功能证据

`realtime_control_fault_functional_001`实际运行63个控制状态，观测断流后从约1.18m/s停至0，恢复新观测后再次运动；阻塞锁存后新包不恢复旧路径。两段轨迹通过既有独立执行审计。该实验仅用已知直道路面和预置路径、模型调用0、TTL为0.3秒，不是完整感知故障/导航到达或性能表。

CPU软件渲染使用输出目录内隔离OSMesa/llvmpipe和PyOpenGL 3.1.7，CUDA_VISIBLE_DEVICES为空；没有安装或修改原conda环境。真实YOLO/MobileSAM/CLIP仍运行，Qwen关闭。CPU试跑的TTL为15秒、单任务70秒，配置为config00-positive0/seed17、全部六条件。此参数为CPU I/O与恢复验证，正式GPU 1.5秒保持；两者不横比性能或到达率。CPU与主矩阵共享主机负载，事件追加到主矩阵资源日志。

首次CPU试跑001因额外gobs字典字段被旧过滤器拒绝而中断，原脚本、来源快照、前端原始输出和失败日志均保留；未获得完整结果或扩展信用。移除该元数据后另立002，增加接口兼容回归测试。准备清单`realtime_faults_prepare_only_001`从未调用模型，修复后已明确标为不执行，不能当作试跑。

是否完成、暴露和到达只读实际summary及原始执行证据。六次CPU条件仍属于同一任务同一种子，不能增加最低正确到达所需的独立任务或配置覆盖。
