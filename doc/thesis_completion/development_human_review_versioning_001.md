# 过去LiDAR开发人工审核的来源与操作

更新：2026-11-12。本文件是已有自动证据上的人工审核操作说明，不是人工结论或新的封存实验协议。用户已同意使用页面提交，实际数量仍以追加记录为准，当前为0。

正式入口：转发服务器8768端口后访问 `http://localhost:8768/visualizations/causal_development_review_002/index.html`。自然指令仍使用 `http://localhost:8768/annotation/natural_command_review_001/index.html`。原8767服务和旧记录保持。门户006起链接新开发页。

## 审核流程

1. 选择114个预设首、中、末帧之一，查看真实RGB、检测、实际CLIP crop、SAM和过去LiDAR。显示RGB是JPEG副本；实际CLIP crop已与模型输入逐像素核验。
2. 选择当前建图方法和待核验检测。先确认是否能看清，再填写可见类别、颜色和细属性；无法确认时使用unknown、证据不足及具体原因。官方大类不自动等于可靠细车型，多帧动态状态不能由单张crop决定。
3. 身份、正确关联、错合并、重复节点或身份变化结论须选择当前方法中的节点；使用节点多选框可选多个。节点和检测之间没有自动预填的身份对应。正确关联还需要填写当前帧可核验的官方实例token。单帧证据不足以确认跨帧身份变化，应保留证据不足，或明确记录额外帧证据而不计成已独立核验。
4. 填写真实审核者与依据，再提交。服务器追加单独JSON记录，返回submission_id；刷新统计可看数量。确认结论不由自动匹配或官方类别默认代填。切换方法会清空上一个方法的身份选择和结论，避免错误复用。
5. 记录收到后仍只有“来源和结构核验通过”身份，标签正确性需后续独立复核及一致性评价；一次提交不自动构成双人审核、可靠覆盖或训练真值。

## 来源约束

新页绑定 `annotation/causal_dev_evidence_001` 的索引SHA、逐帧证据SHA、源预测SHA、真实crop SHA和独立审计清单。任一改变则拒绝，不能把旧未来LiDAR图的身份/合并判断直接搬到过去LiDAR图。记录还保存所选mapping_method和reviewed_node_ids，拒绝其他方法/其他帧的节点。

旧 `corrected_dev_evidence_001` 页面仍按原来源兼容。若RGB和crop实际哈希一致，颜色和可见细属性可以在后续明确核对来源后复用；图身份与关联结论不能直接继承。第一版开发页001在加入方法/节点绑定前仅做了拒绝路径测试，未产生人工记录；正式使用002。

当前表单的单位是已有检测；没有检测的官方对象、跨帧身份长链和多审核者裁决，仍需单独审核清单与来源记录，不能用本页提交数量冒充完成这些要求。全部855真实crop/855掩膜来源已自动核验，不等于855条人工标签。

## 验证及限制

311项项目测试通过，其中版本/内容变化、跨方法节点和缺少身份依据拒绝测试采用临时合成结构，不写项目人工目录。真实桌面/手机浏览器仅读取及发送4份故意错误SHA的提交，全部HTTP400；真实人工记录前后均0。没有发送假装人工的有效提交。真实用户成功提交和标签可靠性仍待发生。

官方sample GT晚于相机约33–42ms；首帧缺测保留。页面和审核均不提供路线、正确锁定或实际到达信用。所有阶段和goal_complete继续为false。
